## Production checkpoint requirements

### Backend/persistence

Replace `localStorage` with the project's production database.

Persist:

- users
- projects
- project members
- issues
- user story details
- notes
- comments
- attachments
- activity events

Use transactions for mutations that generate audit history.

### Authentication

Connect the login screen to real authentication.

Users should land based on role/context:

- Member → My Work / normal workspace
- Project Lead → project workspace
- Executive → Executive overview
- Admin → normal workspace with configuration access

Do not hardcode role based on email.

### Authorization

Implement server-side access control for reads and writes.

Executive access is company-wide read/analysis access; Admin is configuration access. They are not synonymous.

### Hierarchy

Enforce:

```text
Project → Epic → User Story → Task → Sub-task
```

Prevent invalid parent assignments and cycles server-side.

### Issue keys

Use stable human-readable keys such as `PMS-42` with a project-local sequence. Never derive permanent identity from the title.

### Notes

Notes are first-class records with author, category, timestamps, edit history where practical and activity events.

### Attachments

Implement durable object storage. Record filename, MIME type, size, uploader and object key. Downloads must be authorized.

### Activity

Activity must be generated by business mutations, not reconstructed from current state.

At minimum log:

- create
- edit
- status change
- assignee change
- priority change
- parent change
- comment
- note
- attachment
- completion

### Board

Keep Kanban for executable work (Tasks/Sub-tasks by default). Update status with a robust drag/drop library only if one already fits the stack; correctness is more important than animation.

### Executive

Build company-wide:

- project health
- open/high-priority/overdue counts
- team contribution evidence
- master activity log
- filters
- project drill-down

Avoid fake predictive analytics at this checkpoint.

## Tests that must exist before completion

1. Create Project.
2. Create Epic.
3. Create User Story under Epic.
4. Create Task under User Story.
5. Create Sub-task under Task.
6. Reject invalid hierarchy.
7. Reject cross-project parent assignment.
8. Update status.
9. Assign user.
10. Add note.
11. Add comment.
12. Attach file metadata and object.
13. Activity event is persisted for each meaningful mutation.
14. My Work returns only authorized assigned work.
15. Executive can see cross-project activity.
16. Ordinary member cannot access unauthorized project/executive data.
17. Reload preserves all data.
18. Board status movement persists.

## Definition of Checkpoint 1 complete

A real user can sign in and manage a project through:

```text
Project
→ Epic
→ User Story
→ Task
→ Sub-task
→ Assignment
→ Status movement
→ Notes / attachment / discussion
→ Activity history
→ Project progress
→ Team contribution
```

An Executive can sign in and see:

```text
Company portfolio
→ project health
→ team contribution evidence
→ master activity log
→ project drill-down
→ individual issue evidence
```

All core data survives reloads and authorization is enforced server-side.
